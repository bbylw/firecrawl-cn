SDK 把 Firecrawl 的所有端点封装成你所用语言里的原生方法，省去手工拼 HTTP 请求的麻烦，其中最有用的一点是**自动处理异步任务的轮询**：爬取、批量抓取和智能体在 HTTP 层都需要“提交任务再反复查询状态”，而 SDK 会替你等待到完成并直接返回结果。

## 统一的调用模型

所有 SDK 都遵循同一套概念，方法与[功能概览](/docs/features)里的端点一一对应：

| 能力 | 方法 | 端点 |
| --- | --- | --- |
| 搜索 | `search` | `POST /v2/search` |
| 抓取 | `scrape` | `POST /v2/scrape` |
| 交互 | `interact` | `POST /v2/scrape/{scrapeId}/interact` |
| 智能体 | `agent` | `POST /v2/agent` |
| 爬取 | `crawl` | `POST /v2/crawl` |
| 映射 | `map` | `POST /v2/map` |
| 批量抓取 | `batch_scrape` / `batchScrape` | `POST /v2/batch/scrape` |

初始化时传入 API 密钥（或读取 `FIRECRAWL_API_KEY` 环境变量），之后各方法接受与 HTTP 请求体同名的参数。

<Tabs syncKey="fc-lang">
<TabItem label="Python">

```python
from firecrawl import Firecrawl

app = Firecrawl(api_key="fc-YOUR_API_KEY")
```

</TabItem>
<TabItem label="Node.js">

```js
import { Firecrawl } from 'firecrawl';

const app = new Firecrawl({ apiKey: "fc-YOUR_API_KEY" });
```

</TabItem>
<TabItem label="Java">

```java
FirecrawlClient client = new FirecrawlClient(
    System.getenv("FIRECRAWL_API_KEY"), null, null
);
```

</TabItem>
</Tabs>

## 轮询由谁负责

```python
# 爬取是异步任务，但这里直接拿到完整结果
docs = app.crawl("https://docs.firecrawl.dev", limit=50)
for doc in docs.data:
    print(doc.metadata.source_url)
```

同一个操作用 cURL 需要两次调用（创建任务 + 查询状态）和一个轮询循环，见[爬取 Crawl](/docs/features/crawl)。若你更希望自行控制等待策略，也可以绕过 SDK 直接调用 HTTP 接口。
